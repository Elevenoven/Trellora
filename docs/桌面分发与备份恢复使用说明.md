# Trellora 下载、备份与换电脑

当前候选为 Windows x64 的 `Trellora-1.0.0-portable-x64.exe`。下载后直接运行，不需要安装 Node.js、Python 或项目依赖。正式发布验收进度见 [验收记录](verification/desktop-distribution-acceptance.md)。

本地另生成了 `Trellora-1.0.0-setup-x64.exe` 安装候选：按当前用户安装，可选择安装目录，注册 Markdown/TXT 的可选打开方式。安装不修改现有默认应用。独立文件的本机测试和干净 Windows 待验收范围见 [独立文件验收记录](verification/external-documents.md)；这些本地候选尚未签名、未公开发布。

## 打开电脑上的文本文件

1. 左侧“打开”或 `Ctrl+O` 选择 MD、TXT、JSON 等支持的文本文件，无需登记父目录或笔记库。安装版也可从 Windows“打开方式”选择 Trellora；默认应用由用户在 Windows 中选择。
2. 独立文件默认源码模式，Markdown 可切换预览。不带本地引用时可切换可视化编辑；带本地资源时使用源码与预览，以保留引用语法。`Ctrl+S` 保存原文件，`Ctrl+Shift+S` 另存。未明确保存的修改只进入应用私有恢复缓存。
3. 相对图片从文件所在目录读取；越界图片或绝对路径需在“文件操作 → 选择资源目录”建立只读授权。源码中粘贴或拖入图片会先暂存，明确保存后才写入 `<文件名>.assets`。跨目录另存和“加入笔记库”会复制引用资源。
4. “当前文档 AI”默认只读当前草稿；改写和翻译需要源码选区。建议需明确应用，应用后仍需手动保存。选择补充笔记库才读取该库；独立 AI 不自动进入聊天历史或长期记忆。
5. 多个系统打开请求显示在“待打开文件”中。切换和退出时有未保存草稿，会提示保存、放弃、取消。原文件被其他软件修改或删除时保留草稿并提示冲突。

完整工作区备份不包含这些外部原文件及其私有恢复缓存；换电脑前请明确保存，并另行复制外部文件与对应 `.assets` 文件夹。

## 第一次打开

1. 在首页引导中创建或打开笔记库。工作区默认位于系统“文档”中的 `Trellora工作区`，也可以选择其他位置。
2. 可以导入两篇虚构的中文样例，体验待办、链接和搜索。重复导入不会覆盖已经修改的样例。
3. 未配置模型时，编辑、保存、文件浏览和关键词搜索可以直接使用。智能回答和资料语义搜索分别需要语言模型、向量模型；填写配置后点击检测，检测通过才表示当前连接可用。
4. 引导可以跳过，之后在“设置 → 通用 → 首次使用引导”中重新打开。

文本和 DOCX 在本机处理。导入 PDF 时默认只保存本地文件；选择上传后才将本批文件发送给 MinerU。以后单独解析或重试 PDF，也会确认当前文件版本的上传权限。文件内容变化、换电脑恢复后需要重新确认。

## 数据放在哪里

便携 exe 是程序文件，用户数据保存在系统工作区、各笔记库/资料库和当前 Windows 用户的应用配置目录。设置中可以查看工作区，关于与诊断中可以查看实际配置、日志和运行时路径。外部库仍在用户选择的位置，切换工作区不会搬动它们。仅复制 exe 不能迁移这些数据。

同一数据目录只能由一个应用实例使用。重复打开会回到现有窗口；另一配置占用同一工作区或库时，可以退出，或选择其他位置创建独立配置。

## 做完整备份

1. 打开“设置 → 工作区与备份”，核对工作区和外部库列表。工作区内的库自动包含；可以选择需要备份的外部库。
2. 选择与源工作区、库分离的备份目录，然后点击“立即备份”。
3. 捕获副本时应用会先保存草稿，并短暂暂停写入。进入压缩和核对阶段后，可以继续编辑。显示完成后，目标目录中的 ZIP 才是成功备份。

完整备份包含原文、附件、近期笔记备份、索引、会话和记忆；模型名称与去掉凭据的服务地址作为重新配置参考保存，API Key 不导出。备份中的原文应按个人数据保管。

每日快照默认关闭。主动开启后，仅在应用运行时每天生成至多一份成功快照，保留最近 7 份成功的自动快照；手动备份不会自动删除。每篇笔记原有的 3 份近期备份和普通备份间隔继续保留。

## 在本机或另一台电脑恢复

1. 在目标电脑运行 Trellora，打开“设置 → 工作区与备份 → 从完整备份恢复”。
2. 选择 ZIP 和独立的恢复父目录，核对预览中的版本、文件数量、源位置与新位置。可以另外选择导入外观和编辑偏好。
3. 确认后，应用校验文件与数据库，在独立目录中恢复并登记新库。已有工作区和库保留，恢复过程不会合并到它们。
4. 点击“切换到恢复的工作区”读取该工作区的会话和记忆；在库管理中选择恢复的笔记库或资料库查看文件。当前正在使用的笔记库不会被这个按钮自动切换。
5. 参考“备份中的模型连接”重新填写密钥，检测服务。恢复的后台处理默认暂停，准备好后主动点击“恢复后台处理”；PDF 上传仍需重新确认。

若恢复在目录发布或库登记时中断，可在未完成的恢复列表中继续。已经发布的文件不会在登记重试时重新解压覆盖。取消发布前的恢复会清理本操作的暂存目录；文件占用导致无法清理时会保留提示，继续恢复时再次检查。

目前接受 Trellora 格式的完整备份：至多 50000 个数据文件、50000 个目录、1000 个物理根及 1000 个库登记，展开后至多 256 GiB；超限时请按库拆分。

## 更新与排错

在“设置 → 关于与诊断”点击“检查新版本”，查看公开正式版本及下载链接。检查只在点击后进行，结果缓存 5 分钟。更新前先做完整备份，退出应用，再更换 exe；应用不会自动下载、安装或改写用户笔记。

使用安装版时，退出后运行新安装包升级。卸载保留应用私有数据和用户笔记，只清理本安装路径仍拥有的可选打开方式；用户自行设置的 Windows 默认选择由 Windows 管理。

本地文档组件不可用时，笔记仍可使用；先尝试重新下载候选包。需要排查时，在关于与诊断中打开日志目录或导出诊断。导出前会说明其包含的版本、数据路径和服务地址；诊断不包含笔记正文和 API Key。
